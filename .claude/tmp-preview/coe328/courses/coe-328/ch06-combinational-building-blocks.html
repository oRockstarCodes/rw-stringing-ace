Ch 6: Combinational Circuit Building Blocks

Oct 09, 202611 min read

  • coe328

Overview

Readings Brown & Vranesic §6.1–6.5 · Lecture 7 · week 6

Some combinational circuits come up so often that they’re sold as ready-made chips (or used as blocks in CAD tools) instead of being built from gates every time. This chapter covers comparators, decoders (including the BCD-to-7-segment decoder), encoders, multiplexers, demultiplexers, and parity generators/checkers.

Notes

Comparators

A comparator tells you how two binary numbers relate.

Equality. An XNOR gate is a 1-bit comparator: its output is 1 when the two bits are equal. To compare two multi-bit numbers, XNOR each pair of matching bits and AND the results. The numbers are equal only if every bit pair matches.

Figure 6.1: A 2-bit equality comparator.

Magnitude (inequality). A magnitude comparator also has A>B and A<B outputs. To decide, start at the most significant bit:

  • A3​=1 and B3​=0 → A>B.
  • A3​=0 and B3​=1 → A<B.
  • A3​=B3​ → no decision yet; move to the next bit down and repeat.

The first bit position where the numbers differ decides the answer. If no position differs, A=B.

Decoders

A decoder detects a specific bit combination (code) on its inputs and signals it with an output level. In general it has n inputs and up to 2n outputs.

Decoding one code. An AND gate is the basic decoding element because it’s 1 only when every input is 1. Invert the inputs that should be 0. For example, to detect 1001:

X=A3​A2​​A1​​A0​

For an active-LOW output, use a NAND gate instead.

Decoding every code. A decoder that has one output per input combination is called an n-line-to-2n-line decoder, or a 1-of-2n decoder because exactly one output is active at a time.

  • 4-line-to-16-line (1-of-16): 4 inputs, 16 outputs, one AND (or NAND) gate per output.
  • BCD-to-decimal (4-line-to-10-line, 1-of-10): only the 10 valid BCD codes get an output.
  • 2-line-to-4-line: with inputs S1​S0​, the outputs are Y0​=S1​​S0​​, Y1​=S1​​S0​, Y2​=S1​S0​​, Y3​=S1​S0​. Each output is one minterm.

BCD-to-7-segment decoder. Takes a BCD digit and lights the right segments (a–g) of a 7-segment display to show it. Each segment is its own output function of the 4 BCD inputs, simplified with a K-map using the six invalid codes as don’t cares (Ch 4). For segment a, lit for digits 0, 2, 3, 5, 6, 7, 8, 9:

a=A+C+BD+BD

Try it: set a BCD code and see which segments light. Each segment’s expression is listed underneath.

Encoders

An encoder does the reverse of a decoder: it takes an active level on one of its inputs (a digit or symbol) and outputs the matching code.

Decimal-to-BCD encoder (10-line-to-4-line): ten inputs, one per decimal digit, and four BCD outputs. Each output bit is the OR of the digits whose BCD code has a 1 in that position:

Output bitWeight1 for digits…Expression
A3​88, 9A3​=8+9
A2​44, 5, 6, 7A2​=4+5+6+7
A1​22, 3, 6, 7A1​=2+3+6+7
A0​11, 3, 5, 7, 9A0​=1+3+5+7+9

(Here “8 + 9” means the OR of input lines 8 and 9.) Input 0 needs no gate: all outputs are 0 when nothing else is active.

Multiplexers (data selectors)

A multiplexer (MUX) routes one of several data inputs onto a single output line. The data-select inputs choose which one. With n select lines it can choose among 2n data inputs.

4-to-1 MUX: data inputs D0​–D3​, select inputs S1​S0​:

S1​S0​Y
00D0​
01D1​
10D2​
11D3​

Y=D0​S1​​S0​​+D1​S1​​S0​+D2​S1​S0​​+D3​S1​S0​

That’s four 3-input ANDs, a 4-input OR, and two inverters for S1​​ and S0​​. Each AND gate is enabled by exactly one select combination (a decoder built into the MUX). The 2-to-1 MUX from Ch 2, f=sx1​+sx2​, is the smallest case.

Try it: set the data inputs and the select lines. The selected path lights up through the MUX.

Interactive 4-to-1 multiplexer (open this page on the site to use it).

A MUX as a logic function generator. A 2n-to-1 MUX can implement any function of n variables: connect the variables to the select lines, and tie each data input to the function’s output for that row (HIGH for 1, LOW for 0). The MUX then just looks up the truth table, like an FPGA LUT (Ch 3). This usually replaces several gate chips with one MUX chip.

A smaller trick: a 2n−1-to-1 MUX can do an n-variable function. Put n−1 variables on the select lines, and feed each data input with 0, 1, the last variable, or its complement (see Example 5).

Demultiplexers

A demultiplexer (DEMUX) does the reverse of a MUX: it takes data from one line and sends it to one of several output lines, chosen by the select inputs. It’s also called a data distributor.

1-to-4 DEMUX: the data input goes to all four AND gates, and the select lines enable only one of them:

D0​=Data⋅S1​​S0​​,D1​=Data⋅S1​​S0​,D2​=Data⋅S1​S0​​,D3​=Data⋅S1​S0​

The unselected outputs stay at 0.

A decoder is a DEMUX. A decoder with an enable input already has this structure: use the decoder inputs as the select lines and the enable as the data input. For example, a 4-line-to-16-line decoder with two active-LOW chip-select inputs works as a 1-to-16 DEMUX: one chip select carries the data, and the other is held LOW to enable the chip.

Parity generators and checkers

Parity is a simple way to detect a single-bit error. An extra parity bit is sent with the data so that the total number of 1s is:

  • Even parity: even
  • Odd parity: odd

The key fact: the XOR (sum without carries) of an even number of 1s is 0, and of an odd number of 1s is 1. So XORing all the bits together counts the 1s mod 2:

X=bn−1​⊕⋯⊕b1​⊕b0​

  • Generator: XOR the data bits. For even parity the parity bit is X; for odd parity it’s X.
  • Checker: XOR all received bits including the parity bit. For even parity, X=0 means OK and X=1 means an error. (Odd parity: the other way round.)

A single flipped bit always changes the count of 1s by one, so it’s always caught. Two flipped bits cancel out and aren’t.

2-bit equality comparator

(A=B)=A1​⊕B1​​⋅A0​⊕B0​​(6.1)
  • A1​A0​, B1​B0​: the two 2-bit numbers being compared

Decoder outputs

outputs≤2n(6.2)
  • n: number of input lines. Each output is one minterm of the inputs.

4-to-1 multiplexer

Y=D0​S1​​S0​​+D1​S1​​S0​+D2​S1​S0​​+D3​S1​S0​(6.3)
  • D0​–D3​: data inputs
  • S1​S0​: select inputs; the binary number S1​S0​ is the index of the data input passed to Y

1-to-4 demultiplexer

Di​=Data⋅mi​(S1​,S0​)(6.4)
  • mi​: the minterm of the select lines for output i (e.g. m2​=S1​S0​​)

Parity

X=bn−1​⊕⋯⊕b1​⊕b0​(6.5)
  • X=1 when the bits contain an odd number of 1s

Examples

These follow the lecture examples, with different numbers.

Example 1: Comparing two numbers

Like Lecture 7, Example 2 and the magnitude-comparator slides

(a) Is A=10 equal to B=10 using a 2-bit equality comparator? (b) Compare A=1011 and B=1001 with a magnitude comparator.

(a) Bit 1: 1⊕1​=1. Bit 0: 0⊕0​=1. AND: 1⋅1=1, so A=B.

(b) Start at the MSB:

  • A3​=B3​=1: no decision
  • A2​=B2​=0: no decision
  • A1​=1, B1​=0: A>B (bit 0 doesn’t matter)

Check: 11>9 ✓

Example 2: Decoding one code

Like the lecture’s “decode 1001” slide

Write the decoding expression for the code 1011 (A3​ is the MSB), with an active-HIGH output and with an active-LOW output.

  1. Invert the inputs that should be 0 (only A2​ here): X=A3​A2​​A1​A0​(AND gate, active-HIGH)
  2. Active-LOW: use a NAND gate instead: X=A3​A2​​A1​A0​​

The output is 1 (or 0 for active-LOW) only for 1011.

Example 3: Decimal-to-BCD encoder

Like the decimal-to-BCD encoder slide

Input line 6 of a decimal-to-BCD encoder is HIGH (all others LOW). What are the outputs?

  1. Check which output expressions include input 6: A2​=4+5+6+7 and A1​=2+3+6+7 do; A3​ and A0​ don’t.
  2. Outputs: A3​A2​A1​A0​=0110, which is 6 in BCD ✓

Example 7: Parity

Like the parity-checker slide

(a) Find the even and odd parity bits for the data 1011001. (b) The byte 11010110 (7 data bits + even parity bit) is received. Is there an error?

(a) The data has four 1s (even), so X=1⊕0⊕1⊕1⊕0⊕0⊕1=0.

  • Even parity bit: 0 (the total stays at four 1s)
  • Odd parity bit: 1 (makes five 1s)

(b) The received byte has five 1s, so the checker outputs X=1. With even parity that means an error (at least one bit flipped).

Example 8: A 7-segment segment equation

Like Lecture 3, Example 23

Check that a=A+C+BD+BD lights segment a for digit 5 but not for digit 4.

  1. Digit 5 =0101: A=0, C=0, BD=1⋅1=1 → a=1, lit ✓
  2. Digit 4 =0100: A=0, C=0, BD=1⋅0=0, BD=0⋅1=0 → a=0, off ✓ (a “4” has no top bar)

Common mistakes

  • Comparing magnitudes from the LSB. Always start at the MSB; the first difference decides.
  • Mixing up decoders and encoders: a decoder turns a code into one active line; an encoder turns one active line into a code.
  • Reading the select lines in the wrong order. S1​ is the MSB: S1​S0​=10 selects D2​, not D1​.
  • Thinking unselected DEMUX outputs “hold” their old value. They’re 0.
  • For a MUX function generator, tying data inputs to the wrong rows (check that the select variables are wired MSB-first, the same as the truth table).
  • Thinking parity can correct errors or catch two-bit errors. It only detects an odd number of flipped bits.
