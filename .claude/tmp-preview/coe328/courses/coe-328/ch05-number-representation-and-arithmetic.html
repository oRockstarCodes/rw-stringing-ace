Ch 5: Number Representation and Arithmetic Circuits

Ch 5: Number Representation and Arithmetic Circuits

Oct 09, 202612 min read

  • coe328

Overview

Readings Brown & Vranesic §5.1–5.3 · Lecture 6 · week 5–6

The same bit pattern can mean different numbers depending on the representation. This chapter covers unsigned numbers (and octal/hex as shorthand), the circuits that add them (half adder → full adder → ripple-carry adder), the three ways to write signed numbers (sign-magnitude, 1’s complement, 2’s complement), and why 2’s complement wins: one adder circuit does both addition and subtraction. It ends with overflow, when a result doesn’t fit.

Notes

Unsigned numbers

An n-bit unsigned number B=bn−1​…b1​b0​ uses positional notation (see Ch 1):

V(B)=bn−1​2n−1+⋯+b1​21+b0​20

With n bits the range is 0 to 2n−1 (8 bits: 0 to 255).

Always state the representation before reading a bit pattern. 11111011 is 251 unsigned, −5 in 2's complement, −4 in 1's complement, and −123 in sign-magnitude.

Octal and hexadecimal

Both are shorthand for long binary numbers:

  • Octal (base 8): each digit is 3 bits. Group from the LSB in 3s. 101 011 010 1112​=53278​
  • Hex (base 16): each digit is 4 bits. Group from the LSB in 4s. 11 0110 10002​=0011 0110 10002​=36816​
  • Pad with 0s on the left if the bit count isn’t a multiple of 3 or 4: 10 111 0112​=2738​

The half adder

Adding two bits x and y gives a sum bit s and a carry bit c:

xycs

s=x⊕yc=xy

  • XOR gives the sum: it’s 1 when exactly one input is 1.
  • AND gives the carry: it’s 1 only when both inputs are 1.
  • A half adder has no carry-in, so it can only be used for the least significant bit.

The full adder

Every other bit position also has to add the carry coming in from the position to its right. A full adder adds three bits, xi​, yi​, and carry-in ci​:

  • The sum is 1 when an odd number of inputs are 1.
  • The carry-out is 1 when at least two inputs are 1 (the majority function from Ch 2).

A full adder can be built from two half adders and an OR gate (Figure 5.1): the first adds x and y, the second adds that sum to cin​, and either one producing a carry gives a carry-out.

The ripple-carry adder

To add two n-bit numbers, chain n full adders:

  • Full adder i adds bits xi​ and yi​.
  • The carry-out of stage i is the carry-in of stage i+1.
  • For plain unsigned addition, the first carry-in is c0​=0.
  • The last carry-out, cn​, is the extra bit of the sum.

The problem is speed. A carry made in the lowest bit can change the next stage, which can change the next, all the way up the chain. The result isn’t settled until the carry has rippled through every stage, so the worst-case delay grows with n. Faster adders (carry-lookahead, §5.4) compute carries in parallel at the cost of more logic; they’re not covered in this course.

Signed numbers

The MSB is the sign bit: 0 for positive, 1 for negative. Positive numbers look the same in all three systems. They differ in how negatives are written.

Sign-magnitudeflip the sign bit only−127 to +127two (+0 and −0)
1’s complementflip every bit: K1​=(2n−1)−P−127 to +127two (00000000 and 11111111)
2’s complementflip every bit, then add 1: K2​=2n−P−128 to +127one
  • In 4 bits, +5=0101. Then −5 is 1101 (sign-magnitude), 1010 (1’s complement), or 1011 (2’s complement).
  • Since K2​=K1​+1, the easy way to get a 2’s complement in hardware is: invert, then add 1.
  • 2’s complement gets one extra negative number: it has only one zero, so the pattern 10000000 that would have been −0 is −128 instead.

Reading a 2’s complement number: if the MSB is 0, read it normally. If it’s 1, take the 2’s complement to find the magnitude and put a minus sign in front. (11110111 → 00001001=9 → −9.) Or: give the MSB a weight of −2n−1 instead of +2n−1.

Adding signed numbers

1’s complement addition sometimes needs a fix: if there’s a carry-out of the sign bit, add it back into the LSB (the end-around carry). That second addition can double the time, which is why 1’s complement isn’t used for arithmetic.

(+5)+(−2):0101+1101add the carry back:0010+1​=10010=0011=+3✓​

2’s complement addition always works directly. Add the bit patterns with an ordinary adder and ignore any carry out of the sign bit. The signs of the operands don’t matter.

SumBitsResult
(+5)+(+2)0101+00100111=+7
(−5)+(+2)1011+00101101=−3
(+5)+(−2)0101+11101​0011=+3
(−5)+(−2)1011+11101​1001=−7

2’s complement subtraction: negate the subtrahend (take its 2’s complement) and add:

A−B=A+B+1

A helpful picture is the number circle: in 4 bits the patterns 0000 to 1111 go around a circle, with 0111 (+7) next to 1000 (−8). Adding moves clockwise, subtracting moves counterclockwise, and crossing the +7/−8 boundary means the answer is wrong (overflow).

The adder/subtractor unit

One n-bit adder can do both operations, controlled by a signal Add/Sub (0 = add, 1 = subtract; the bar over Add means “add when this is 0”):

  • Each bit yi​ goes through an XOR gate with the control signal. XOR with 0 passes yi​ through; XOR with 1 inverts it. So the adder sees Y when adding and Y when subtracting.
  • The control signal is also the carry-in c0​. When subtracting, c0​=1 supplies the “+1” that turns Y into the 2’s complement.

Add (control=0):X+Y+0Sub (control=1):X+Y+1=X−Y

Try it: set X and Y, switch between add and subtract, and follow the carries through the four full adders.

Arithmetic overflow

With n bits, a 2’s complement result must be between −2n−1 and 2n−1−1 (4 bits: −8 to +7). If the true answer is outside that range, the result is wrong: arithmetic overflow.

  • Only possible when adding two numbers with the same sign. A positive plus a negative always fits.
  • Sign check: overflow happened if two positives give a negative, or two negatives give a positive.
  • Carry check (what the hardware uses): overflow = cn​⊕cn−1​, the carry out of the sign bit XOR the carry into it.
Sum (4-bit)Bitsc4​c3​Overflow?
(+7)+(+2)0111+0010=100101Yes (got −7, not +9)
(−7)+(+2)1001+0010=101100No (−5)
(+7)+(−2)0111+1110=1010111No (+5)
(−7)+(−2)1001+1110=1011110Yes (got +7, not −9)

For unsigned numbers the rule is different: the result is wrong when cn​=1 (the sum needs one more bit).

Unsigned value

V(B)=i=0∑n−1​bi​2i,0≤V≤2n−1(5.1)
  • bi​: bit i (b0​ is the LSB)
  • n: number of bits

Half adder

s=x⊕y,c=xy(5.2)

Full adder

si​=xi​⊕yi​⊕ci​,ci+1​=xi​yi​+xi​ci​+yi​ci​(5.3)
  • xi​, yi​: the two operand bits at position i
  • ci​: carry into position i
  • si​: sum bit at position i
  • ci+1​: carry out of position i (into position i+1)

Complements

K1​=(2n−1)−P,K2​=2n−P=K1​+1(5.4)
  • P: the positive number being negated
  • K1​, K2​: its 1’s and 2’s complement (the bit patterns for −P)

2’s complement subtraction

X−Y=X+Y+1(5.5)
  • Y: Y with every bit inverted

Signed range (n-bit 2’s complement)

−2n−1≤V≤2n−1−1(5.6)

Overflow (2’s complement)

Overflow=cn​⊕cn−1​(5.7)
  • cn​: carry out of the sign bit
  • cn−1​: carry into the sign bit

Examples

These follow the lecture’s worked examples and practice questions, with different numbers.

Example 1: Hex, octal, and decimal

Like Practice 1

Convert 101101102​ to hex, octal, and decimal.

  1. Hex (groups of 4): 1011 0110=B616​
  2. Octal (groups of 3 from the right, pad to 010 110 110): 2668​
  3. Decimal: B616​=11×16+6=182. Check in binary: 128+32+16+4+2=182 ✓

Example 2: Full adder outputs

Like Practice 2–3

Find s and cout​ for a full adder with x=1, y=0, cin​=1, and explain why a half adder couldn’t do this.

  1. Sum: 1⊕0⊕1=0 (an even number of 1s).
  2. Carry: xy+xcin​+ycin​=0+1+0=1 (two of the three inputs are 1).

So 1+0+1=102​: s=0, cout​=1. A half adder only has two inputs, so it has nowhere to take the carry-in.

Example 4: Subtraction with 2’s complement

Like the lecture’s “13 − 5” worked example

Compute 22−9 using 8-bit 2’s complement.

  1. Operands: 22=00010110, 9=00001001
  2. Negate 9: invert → 11110110, add 1 → 11110111
  3. Add: 00010110+11110111=1​00001101
  4. Drop the carry out of the 8-bit word: 00001101=13 ✓

Example 5: A negative result

Like Practice 4

Compute 14−25 using 8-bit 2’s complement.

  1. Operands: 14=00001110, 25=00011001
  2. Negate 25: invert → 11100110, add 1 → 11100111
  3. Add: 00001110+11100111=11110101 (no carry out)
  4. Read it: the MSB is 1, so it’s negative. Its 2’s complement is 00001011=11, so the result is −11 ✓

Example 6: Three signed representations

Like the lecture’s signed-number table

Write −37 in 8-bit sign-magnitude, 1’s complement, and 2’s complement.

  1. Start from +37: 00100101
  2. Sign-magnitude: set the sign bit → 10100101
  3. 1’s complement: flip every bit → 11011010
  4. 2’s complement: add 1 → 11011011

Example 7: 1’s complement addition

Like Figure 5.9

Add (−4)+(−2) in 4-bit 1’s complement.

  1. Operands: +4=0100→−4=1011; +2=0010→−2=1101
  2. Add: 1011+1101=11000
  3. End-around carry: there’s a carry out, so add it to the LSB: 1000+1=1001
  4. Check: +6=0110, so −6=1001 ✓

Example 8: Detecting overflow

Like Figure 5.14 and Practice 5

In 4-bit 2’s complement, does (a) (+5)+(+4) or (b) (−6)+(−3) overflow?

(a) 0101+0100:

  • Bits 0–1 produce no carries; bit 2 is 1+1=10, so c3​=1; bit 3 is 0+0+1=1, so c4​=0.
  • Result 1001. c4​⊕c3​=0⊕1=1: overflow. Two positives gave a negative (−7); the true answer +9 needs more than 4 bits.

(b) 1010+1101:

  • Bits 0–2 produce no carries (c3​=0); bit 3 is 1+1=10, so c4​=1.
  • Result 0111. c4​⊕c3​=1⊕0=1: overflow. Two negatives gave a positive (+7); the true answer −9 is below −8.

Example 9: Adder/subtractor unit

Like Figure 5.13

A 4-bit adder/subtractor has X=0110, Y=0011, and the control set to Sub (1). What does the adder see, and what’s the output?

  1. XOR gates invert each yi​: the adder’s second input is Y=1100.
  2. Carry-in c0​=1.
  3. Add: 0110+1100+1=1​0011
  4. Result 0011=3, and 6−3=3 ✓. c4​=1, c3​=1, so no overflow.

Common mistakes

  • Reading a bit pattern without fixing the representation first.
  • Using a half adder where there’s a carry-in. Only bit 0 can use a half adder.
  • Forgetting the +1 when subtracting with 2’s complement (it’s the carry-in in hardware).
  • Keeping the carry out of the sign bit in 2’s complement. It’s ignored (in 1’s complement it’s added back).
  • Calling it overflow whenever there’s a carry-out. For signed numbers, check cn​⊕cn−1​ (or the signs), not cn​ alone.
  • Thinking the 8-bit 2’s complement range is symmetric. It’s −128 to +127.
