3. Variables

3. Variables

Oct 09, 202610 min read

  • coe318

Overview

Readings Lecture 3 · weeks 2–4 · Reference ch. 3

This chapter is about what Java is actually doing with variables as a program runs: overloading and constructors, the this keyword, the different kinds of variables, casting, where things live in memory (stack vs heap), what happens when references are copied, and arrays.

Notes

Method overloading

Overloading means several methods share a name but have different signatures: a different number of parameters, or different parameter types.

Java picks which one to run from the arguments: accelerate() adds 10, accelerate(25) adds 25. (This isn’t allowed in C.)

Changing only the return type is not overloading. int f(int x) and double f(int x) won't compile together, because a call f(3) can't tell them apart.

Mutable vs immutable classes

  • Mutable: the object’s state can change after it’s created (it has setters). Car is mutable, which makes sense since speed and fuel naturally change.
  • Immutable: state is set once, in the constructor, and can never change. No setters, and the fields are private.

Immutability protects data that shouldn’t change after creation (a licence plate, a voter registration) from buggy or malicious code.

To check if a class is immutable, look for two things: all fields private, and no method that changes a field after construction.

Constructors

A constructor initializes a new object. Its rules:

  • Same name as the class
  • No return type, not even void
  • Runs automatically on new

The default constructor. If you write no constructor, Java generates a no-argument one that does nothing. As soon as you write any constructor, that free one disappears.

Constructors can be overloaded like methods. Add public Car() { } and both calls work.

The this keyword

this is a reference to the current object, the one the method or constructor was called on. Writing speed inside a method is really shorthand for this.speed.

Type conversion and casting

Widening (small → large type) happens automatically and is safe:

byte→short→int→long→float→double

Narrowing (large → small) can lose information, so Java makes you ask for it with a cast: put the target type in parentheses.

The cast must happen before the division. (float)(total / count) is still 1.0, because the integer division already threw away the fraction.

References and garbage collection

Assigning one reference to another copies the address, not the object:

After the last line, both variables refer to the "ABC" car. The no-argument Car that sedan used to point at has no references left, so it’s eligible for garbage collection. Java tracks how many references point at each heap object; at zero, the garbage collector can reclaim the memory. You never free memory yourself.

Arrays

An array holds a fixed number of values of one type (primitive or object), indexed from 0 to N - 1.

  • An index outside 0 … length - 1 throws ArrayIndexOutOfBoundsException at run time
  • An array is an object, so the variable is a reference. alias = scores; makes both names point at the same array.

C-style int scores[10]; does not compile in Java. Size goes with new: int[] scores = new int[10];

Example 4: Two names for one array

Lecture 3, arrays in memory

  1. (a) alias and integerArray point at the same array, so changing alias[3] changes integerArray[3]. Prints 10.
  2. integerArray now points at a new 3-element array. alias still points at the old one.
  3. (b) The new array only has indices 0–2, so this throws ArrayIndexOutOfBoundsException and the program stops.

Common mistakes

  • “Overloading” by changing only the return type
  • Adding a constructor with parameters and then calling new X() without writing a no-arg one
  • speed = speed; in a constructor: forgot this., so the field never gets set
  • Casting too late: (double)(a / b) still does integer division
  • Using a local variable before assigning it (compile error, no default value)
  • Thinking b = a; copies an object. It copies the reference; both now share one object.
  • Creating an array of objects and forgetting to new each element, then getting a NullPointerException
  • Indexing a[a.length]: the last valid index is a.length - 1
